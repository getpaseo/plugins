Better Paseo redraws agent conversations as compact rows for tool calls, reasoning, replies, prompts, checklists and errors, and adds a Tasks board for every agent on the host. It continues [Beautiful Chat](https://github.com/ABorakati/beautiful-chat), with desktop hover previews, a block details panel, richer selection and copying, and block-by-block streaming Markdown.

Tool calls start collapsed; chosen open and closed states survive completion and remounts. On desktop a click expands a row, and hovering a collapsed row or file path shows a preview that can wrap, number lines, move, resize, maximize or open in a side panel. On touch devices a tap opens the row in a drawer or panel that steps through the turn's blocks, and a long press offers its copy actions; a pinch or the details text size setting changes that panel's text size. An image viewer provides zoom and pan.

Code, diffs and shell output receive syntax highlighting. Copy text, code, paths, tool results or tables, including a block of cells selected by holding a cell and dragging; desktop table controls also support copying an image. Where a composer is available, selected text can be added to the draft for a later message. Completed replies show copy controls and available model, time and duration information. On iOS a finished reply uses Paseo's native Markdown text, so a range can be selected and a double tap selects one block; a reply that is still streaming is drawn as plain text until it settles.

The Tasks board lays out every agent of the host in lanes: waiting, running, to review, done and archived. Cards show the model, thinking level, project, branch, labels, timer and subtasks, and sub-agents a provider runs itself, such as Claude Code's Agent tool, get read-only cards. The board can be searched, filtered by project, workspace, agent and label, sorted, and drawn with narrow, default or wide lanes. Search highlights the matching text on cards and, at a card's foot, lists matches in fields the card does not show, such as the first prompt, full path, task ID, PR title or a label folded into +N. While first prompts load, the search field shows a spinner in place of its magnifier, and the filter bar notes tasks whose first prompt was not searched or could not be read, with a Retry for the failed ones. Cards whose directory or workspace is no longer available show a marked corner with the reason, and actions that would fail are disabled. Desktop toolbar and card-menu actions have keyboard shortcuts. A click opens a card's properties, first prompt, last reply, token usage, activity and subtasks in a sidebar, a floating panel or bottom sheet on narrower boards, or a sheet on phones. Cards can stop an agent, or a parent with its running subtasks; answer tool, plan and mode permission requests; mark a finished or failed agent read; archive or unarchive it; and rename it from the card menu, either by hand or with **Automatically update title**, which asks a model for a title and reveals the response while a light sweeps across the card. The rename editor also offers **Generate title**, which fills an editable draft; only **Save** renames the agent, and **Cancel** or dismissing the editor discards that draft. Archived cards offer the same title actions without unarchiving the agent. During card-menu title generation, a card stays in its lane position until the complete title is displayed; its final snapshot and ordering then apply. Other cards and cross-lane status transitions continue to update. Questions open the agent's tab.

## Setup and settings

Requires Paseo 0.12.0 or later. No separate service account is needed. Open **Settings → Plugins → Better Paseo** to choose reply styles, spacing, fonts, previews and block details, and to configure the Tasks board beside a live preview of it, including title generation’s optional custom provider/model, thinking level and prompt. By default it follows the card agent’s provider and model, with thinking disabled where supported or set to the lowest supported level. Turning off **Disable title thinking** follows the source agent’s or custom model’s thinking setting. **Save title settings** shares these settings across clients connected to this host, and **Reset title settings** restores their defaults. The board is on by default and can be turned off there. Settings support English and Simplified Chinese. The Git preparation step installs the committed, locked npm dependency tree without development tools, then runs `scripts/build-client.mjs --install`, which uses the installed esbuild to write a minified client entry and the Tasks board's code into the install directory. The plugin server sends the board's code to a client when the board, its sidebar entry or its settings first show.

## Data access and limits

The plugin reads displayed conversation text, tool results and agent metadata. Syntax highlighting sends displayed code to the daemon. Local-image previews read files on the daemon and return image bytes to the connected client; supported images larger than 3 MB are not inlined. Pressing a file path on desktop opens it on the daemon's machine: on macOS a file opens in its default app and a folder in Finder, while app bundles, recognized script and installer types, and files with an execute bit are only revealed in Finder; Windows and other systems show it in the file manager. The board's open-folder action does the same for an agent's directory. Selected text added to the composer reaches the selected agent provider when you submit the message.

With Tasks enabled and sidebar counts shown, the sidebar subscribes to agent status and attention on the host. Opening the board, or hovering, focusing or touching its entry, also reads agent details, workspaces, projects, labels and model names, including archived agents while the archived lane is shown. These additional subscriptions can remain active for up to 30 seconds after closing the board. The details and the board's search read the start or end of agents' timelines for the first prompt, last sent message and last reply; reading a stored agent's timeline makes the daemon load it, so search skips stored agents and the details read one only when asked. Retry re-reads failed first prompts for agents that are still open; changing the set of searchable tasks or their last-message metadata also restarts the search reader. Cards display agent titles, models, working directories, branches, labels, permission requests and token usage. While the board is open and visible, it asks the plugin server about the cards it holds every 30 seconds, in batches of up to 100 agents; the server refreshes each agent's record, checks that the working directory in that record exists and can be listed (file metadata only, no contents), that its workspace remains, and that the agent's provider and the title provider and model are enabled and selectable. Only paths from the host's agent records are checked, never paths sent by a client. Rename, title generation, Unarchive and Mark as read check the directory again before they act.

Title generation runs only when **Automatically update title** or the rename editor’s **Generate title** is chosen. The server reads the first user/assistant conversation round and the latest four rounds, deduplicates overlaps, and excludes tools, reasoning and other non-conversation entries. Each user message is limited to 4,000 characters and each assistant message to 2,000 characters. These excerpts and the configured prompt go to a helper agent on the source agent’s provider/model, or the custom provider/model when enabled. The settings page lists enabled providers and their selectable models; generation requires the selected model to be available. The default prompt asks for the first user message’s language and a title of at most 80 characters.

The helper runs in a background workspace on a neutral directory inside the plugin’s data directory, under the source agent’s project, with a system prompt that tells it not to use tools. The no-tools instruction is a prompt, not a tool-disable setting; the helper uses the chosen provider’s agent permissions. Its workspace is archived when generation finishes, but its history remains and it can trigger host notifications. Closing the rename editor discards the draft without cancelling the helper or its provider request. A valid final response is a single-line title of at most 80 characters. The card-menu action applies it only if the agent still exists and its title has not changed during generation, including when it is archived; the editor’s preview never renames the agent until **Save**.

The plugin server records each turn's start, end, available token usage and, for a turn that failed, its error message per agent in the plugin's data directory on the daemon, including when the Tasks board is disabled. It keeps the latest 500 turn records per agent and saves markers there for agents stopped or marked read through the board; a marker is cleared when the agent starts a new turn or is archived, or after 30 days. To show a running turn's session token total in the details, the server reads token counts from the provider's own session files on the daemon: Claude Code's under `projects` in `CLAUDE_CONFIG_DIR` (default `~/.claude`), and Codex rollouts under `sessions` in `CODEX_HOME` (default `~/.codex`).

Stop runs `paseo agent stop`, and Unarchive runs `paseo agent inspect` and then `paseo agent reload` for an archived agent. The server looks for the CLI in `PASEO_CLI` (set by the Paseo desktop app), then as `paseo` on its command path, then as the `@getpaseo/cli` installed with the daemon, used only when its version matches the daemon's `@getpaseo/server` and run with the plugin process's Node; without one, Stop and Unarchive are hidden. For features the plugin API does not offer, the server opens short-lived connections to its own daemon with the client modules Paseo installs, using the daemon address and local credential under `PASEO_HOME`. Mark as read clears the agent's attention; renaming a card sets the agent's title in Paseo; label colours and project icons are read where the plugin API does not provide them; provider sub-agents and their timelines are listed. From the first agent turn, or the first session opened from storage, the server also follows the daemon's provider sub-agent updates and lists the sub-agents of every loaded, unarchived agent, kept in memory, including when the Tasks board is disabled. Without that connection Mark as read is hidden, labels take a colour picked from their name, projects show an initial and no sub-agent cards appear. Archive uses the plugin API. Permission buttons send the same responses as Paseo's own controls.

Presentation preferences and most Tasks options use daemon settings shared by every client of the daemon; presentation preferences also keep a browser cache. The board's layout switches for subtasks, the archived lane, groups with no active tasks and lane width are kept on each device, in browser storage on web and the app's storage on iOS and Android, seeded once from the daemon's values. The plugin also reads the host's appearance preferences to follow its fonts and theme. The optional `/bc-perf` command enables diagnostic probes; `/bc-perf dump` writes a diagnostic snapshot, including agent identity, timing and client metadata, to the daemon's temporary directory.

Some interactions depend on the host and input device. Permission approvals in the timeline remain owned by Paseo. Turning off plugin Markdown restores Paseo's reply rendering, including Mermaid and its full footer. Large expanded blocks can still be slow on development simulators. A plugin cannot keep an archived agent's tab open, so an archived task offers Unarchive where Open was.
