Smart Session shows when your Claude plan will run out at the current pace, how full each session's context is, and lets Claude Code agents in Paseo save task state and compact themselves. It records context and plan usage over time and turns that into a forecast, a usage chart and the last 14 days of session windows. It requires Paseo 0.14.0 or later. Context hooks and Claude usage tracking are aimed at Claude Code; interactive Claude and Codex sessions receive the local Smart Session MCP tools. The MCP runs with Node or the Paseo app’s own runtime.

The plugin never compacts a session on its own. A hook asks an agent whether to compact when its context passes a threshold, and the agent can compact, defer or keep working. Settings cover turning Smart Compact off, the thresholds for large and small context windows, automatic enrolment, the composer pill, and whether the plugin registers its hooks.

On load, when you change the hook-registration setting, and when you open its install status, the plugin edits Claude Code configuration on the daemon host. It adds hook entries that run scripts from this plugin to Claude Code's `settings.json`, leaving other entries alone, keeping a backup and removing its own entries when you turn the setting off. Normal startup attaches the MCP to each interactive Claude or Codex session as it opens, resumes, refreshes or imports, while preserving any existing global MCP entry. The plugin must be enabled; the session label `plugin-tools/enabled: "false"` opts out. The local MCP receives the session ID and daemon connection configuration, including a password or password-file path when configured, to invoke Smart Session’s daemon RPCs. Context, usage and task-state results returned by its tools reach the calling agent and its model provider.

For usage history, the plugin periodically reads your Claude Code OAuth token, from its credentials file or the macOS keychain, and uses it to request plan usage from `api.anthropic.com`, without storing or logging the token. If it finds no token it sends nothing, and it falls back to the Paseo daemon's usage reading and to Claude Code's cached usage in `~/.claude.json`. It also reads Claude Code transcripts to attribute token spend and connects to the local daemon, using a daemon password from the environment or a password file when one is required. Its logs, settings and per-agent task-state files are stored under `$PASEO_HOME/plugin-data/smart-session/`.

Pause at the limit (Session Guard) is optional and off by default. Turn on **Pause at the limit** from the Smart Session overview or its settings to pause protected sessions at the configured session-usage threshold (100% by default) and continue the same conversation after a fresh usage report confirms capacity has reset. You can opt individual sessions out, disable automatic continuation, cancel a waiting continuation, or use the pause card’s Resume now and Dismiss pause controls. Resume now opts that session out and continues immediately; Dismiss pause opts it out and releases suspended workers without sending a message.

With native coverage enabled, Linux Claude and Codex provider workers and their nested processes are suspended with SIGSTOP and resumed with SIGCONT. Ownership is checked against the local daemon, agent ID and process birth identity. Native coverage needs Linux and access to /proc; if ownership cannot be confirmed, protection reports an error and retries. Turn native coverage off on unsupported hosts to use foreground interruption and a continuation message instead. Suspension cannot undo requests already sent, and tools can retain locks or time out. Usage detection depends on provider report freshness; Claude also uses the existing recorder’s latest accepted reading. Continuations reach the session’s configured provider.

Pause history, process identities and per-session choices persist under `$PASEO_HOME/plugin-data/session-guard/`, shared with the standalone Session Guard plugin. While that plugin is configured and enabled, Smart Session leaves protection to it. Disable or uninstall the standalone plugin to hand over saved choices and waits; reapply custom host settings. Pauses can survive plugin or daemon restarts, but a full restart loses native process state and resumes the saved conversation with a message after reset. New user work, closed sessions and opt-outs cancel the old continuation. Unconfirmed message delivery requires manual inspection. Turning the feature off releases suspended workers while message continuations remain on hold until re-enabled or cancelled. The paused-session view, timeline cards and optional workspace labels show saved waits.

Agent tool calls such as checking context or saving task state show in the chat as one-line rows, and compaction requests and continuations as cards.

If you run ZeroSub (`@kapybara/zerosub`) to switch between several Claude or Codex accounts, Smart Session reads its account registry and usage readings under `$PASEO_HOME/zerosub/` and its plugin preferences, read-only. It never opens ZeroSub's account homes or credentials. With it, an agent is measured on its own account, and Smart Session leaves an agent to ZeroSub when another account has room. The account name you chose and its usage reach the agent through `budget_status`.

The overview and display settings are available from Command-K. Display settings can hide the sidebar entry and composer button independently without disabling the feature.
