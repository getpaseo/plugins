MCP Tools adds an `MCP n` pill above the composer that lists the MCP servers available to the current agent, grouped by where each one is configured. Opening a server shows its health (status, latency, instructions) and tool list with search, and any tool can be run directly from a form generated from its input schema, without asking the agent. A Diagnostics view shows the config files and agent records checked for the agent's provider. Health checks refresh every 30 seconds while the panel is open, and you can change that rate or pause it in the plugin's settings.

Servers are found by reading the provider's MCP config on the daemon host (for example `~/.claude.json`, `~/.codex/config.toml`, `~/.pi/.mcp.json` or the OpenCode config), running `opencode mcp list` through the OpenCode CLI to discover its active servers, the MCP servers Paseo stored for the agent, and Paseo's own MCP endpoint, which appears as `Paseo (Builtin)`. Providers with a probe are Paseo, Antigravity, OpenCode, Pi, Claude and Codex. The plugin's documentation says Codex support is provided as is. For Pi it also honors `PI_CODING_AGENT_DIR`. The servers must already exist in the provider's config, and an HTTP server that needs authentication must have its headers configured there. For the built-in Paseo endpoint the plugin sends `PASEO_PASSWORD` as a bearer token when it is set, and reads `PASEO_HOME` (default `~/.paseo`) to find the daemon's MCP settings.

Health checks and tool runs connect to each server with its configured credentials. For a stdio server the daemon host starts the configured command, and for an HTTP or SSE server it connects to the configured URL with the configured headers. Tools run with whatever authority that server has, so a tool you run can change the systems it is connected to. Config previews and the Diagnostics view can include provider configuration content, and some previews are not masked, so they may show secrets such as tokens or headers stored in that config.

By default the plugin also adds an MCP server named `gateway` at `http://127.0.0.1:37374/mcp` to every new agent, unless the request already has a server with that name. This is controlled by the `gatewayInject` setting (on by default) and the `gatewayUrl` setting, and it only does something useful if a gateway is running at that address. Turn `gatewayInject` off in the plugin's settings if you do not run one.

The manifest requires Paseo 0.8.0 or later.
